# Content-hash flat storage on Cloudflare R2, with manifest indirection

A published Bundle is stored as a flat content-addressed keyspace under its slug in **Cloudflare R2**. Every file — markdown and assets alike — is hashed (SHA256) over its **raw bytes** and written to `r2://documents/<slug>/<sha256>.<ext>`, PUT with `Cache-Control: public, max-age=31536000, immutable`. The original directory structure and filenames are **not encoded in R2 keys at all**; they live in the **Bundle Manifest** in Postgres (`documents.manifest`), which maps each project-root-relative logical path (`index.md`, `sub/b.md`, `imgs/logo.png`) to its content hash and byte size, plus `root_path` naming the Root entry and `project_root` recording the publisher's absolute project root. Markdown is stored **byte-identical** to what the user wrote — no link rewriting at upload time. Reference resolution happens at view time, server-side, by manifest lookup (ADR-0010); the Manifest is never sent to a client. Blobs are namespaced per slug with **no cross-document sharing**, so a slug's whole `documents/<slug>/` prefix is authoritative for its bytes and "delete the prefix" is always safe — no refcounts, no key ledger (ADR-0005).

We chose manifest indirection over **link-rewrite-at-CLI** (rewriting markdown to embed `<hash>.<ext>` URLs directly) because under rewriting, changing one asset forces every markdown file referencing it to be re-hashed and re-uploaded, and cycles between markdown files become a chicken-and-egg hash problem. With indirection each file's hash is independent of every other's: content integrity is end-to-end (local bytes == stored bytes == hash), and an asset change touches exactly one R2 blob plus one Postgres row. We chose flat content-hash keys over **preserving the original tree in R2 paths** because hash filenames make the CDN cache immutable forever — no invalidation logic for assets, ever — and a flat keyspace has no path-traversal or case-sensitivity edge cases. We chose **R2** over S3+CloudFront and B2 primarily because viewer traffic is read-heavy and worldwide while R2 charges zero egress (S3 charges roughly $0.09/GB out), and R2's S3-compatible API keeps a migration path open; the R2 custom-domain connector also puts `cdn.mdfly.dev` in front of the bucket without any backend hop (ADR-0011). The costs we accept: mild Cloudflare coupling (the custom-domain connector is Cloudflare-only by definition, and the edge posture in ADR-0011 leans on the same vendor); the backend must read the Manifest from Postgres on every cache-missing view, mitigated by aggressive edge caching keyed on `(slug, manifest_hash)` and single-flight at the origin; and identical bytes published under two different slugs are stored twice, since cross-document dedup was rejected — it would buy little at this scale and would cost a refcount table plus a cross-document GC.
