# Edge: Cloudflare registrar + DNS + proxy, subdomain split, apex Worker-routed to Pages or backend

`mdfly.dev` is registered at **Cloudflare Registrar** (at-cost renewal) with **Cloudflare as authoritative DNS**, so the proxy, the R2 custom-domain connector, edge cache, WAF, and Universal SSL all live in one dashboard. Five hosts, each with its own origin and cache posture:

- **`mdfly.dev`** (apex, proxied) is fronted by a small **Cloudflare Worker** that dispatches by path between two origins. **Cloudflare Pages** (built from `apps/landing/`) serves the static marketing and legal set by exact match — `/`, `/about`, `/pricing`, `/terms`, `/privacy`, `/contact`, `/abuse`, `/robots.txt` — plus the prefix `/_landing/*` for its hashed assets. The **Go backend** serves everything else: the slug catchall `/<slug>[/<key>]` and the LLM twin `/llm/<slug>[/<path>.md]` (ADR-0010), the Viewer's `/_static/*` bundle, the OAuth chooser `/cli/login` (ADR-0007), and `/healthz`. The Worker's static-route table is **code-generated from the same source as `internal/slug/reserved.go`**, so the apex path namespace and the reserved-words blocklist cannot drift.
- **`api.mdfly.dev/v1/*`** goes straight to the backend with **no Worker on the path** and **blanket cache-bypass**. This is the CLI's compiled default (`MDFLY_API`). CORS allowlists `https://app.mdfly.dev` and the local dev origin; CLI requests carry no `Origin` and are unaffected.
- **`cdn.mdfly.dev/*`** is the R2 bucket via Cloudflare's native **custom-domain connector** (not S3-compat presigned GETs), caching forever from the PUT-time `immutable` header, never touching the backend. A **CORS rule allows the `https://mdfly.dev` origin** so the Viewer's Raw toggle can `fetch()` the source blob.
- **`www.mdfly.dev`** 301s to the apex via Cloudflare Bulk Redirect — no Worker invocation, no backend involvement.
- **`app.mdfly.dev`** is reserved for the v2 dashboard and is **DNS-unprovisioned in v1** (NXDOMAIN).

The apex is a **proxied A record to the origin VM's reserved static IP** (ADR-0003). Cloudflare terminates TLS at the edge; the origin terminates again with a **Cloudflare Origin CA cert** (15-year, trusted only by Cloudflare) under SSL/TLS mode **Full (strict)**, so learning the origin IP buys an attacker nothing. The origin terminator is **Caddy**, a sibling container beside the Go process (ADR-0003) and the only one there publishing a host port; because it is now the process's TCP peer, it also **strips `CF-Connecting-IP` from any request whose own peer is outside Cloudflare's published ranges**, which is the edge-side half of the rate-limit subject's trust chain (ADR-0013). **Cache rules** per host: apex slug and LLM routes cache-everything respecting the backend's `max-age=300, s-maxage=86400`; `/_static/*` caches on its content hash; Worker forwards to Pages inherit Pages' defaults (hashed assets immutable, HTML short with purge-on-deploy); `api.` bypasses entirely; `cdn.` caches forever. Tier-Cache is on to compress edge-miss fan-out through one upper tier. **Invalidation on commit and delete** is durable, not lazy — see ADR-0012. **Security posture** ships Cloudflare-defensive defaults: Bot Fight Mode on, Security Level Medium, Managed Challenge for borderline traffic, free WAF Managed Rules on, Always-Use-HTTPS, HTTP/3 and 0-RTT on, min TLS 1.2, plus an edge rate-limit of 10 req/min per IP on `api.mdfly.dev/v1/publish/*` and `/v1/update/*` as L1 beneath the app limiter (ADR-0013). **HSTS is deliberately off in v1** — it sticky-bricks the domain if HTTP is ever served; enable after one to two months of stable HTTPS-only operation. **Email DNS** advertises null-MX (`MX 0 "."`, RFC 7505), `SPF v=spf1 -all`, and `DMARC p=reject`, since there is no transactional email to send and spammers probe new domains. **Indexing**: every user Document is noindex — `robots.txt` serves a blanket `Disallow: /` with explicit `Allow:` lines for the Pages-served static paths, and every slug and LLM response carries `X-Robots-Tag: noindex, nofollow` so the header catches crawlers that ignore the file.

We chose **Cloudflare for registrar, DNS, proxy, R2 connector, WAF, and cache** rather than splitting vendors because every one of those is free at this scale, and the alternatives add a second vendor for zero dollars saved and a worse R2 story (the custom-domain connector is Cloudflare-native by definition). We chose the **orange cloud on the apex** over DNS-only because ADR-0010's view path explicitly relies on `s-maxage=86400` to keep the backend off the per-view hot path, with DDoS absorption and origin-IP hiding as bonuses. We chose **R2 custom-domain over presigned GETs** because public Documents (ADR-0001) gain nothing from presigning — the URL is already unguessable via slug plus content hash — and presigning puts CPU per request on a backend that should never see asset traffic. We chose **Origin CA over Let's Encrypt** because the cert is Cloudflare-only-trusted (rejecting anyone who bypasses the edge to hit the origin), valid 15 years with no renewal cron, and free, where Let's Encrypt is a 90-day renewal plus challenge wiring for a single client. Full (strict) is non-negotiable: "Flexible" sends plaintext to origin, making Cloudflare itself the MITM, and plain "Full" accepts a self-signed origin cert. We chose **Worker + Pages at the apex** over embedding the landing site in the backend: the load argument is weak (edge cache means a handful of origin hits per day for static routes), but the operational separation is real — marketing copy and backend code change at different cadences, have different blast radii (static HTML cannot leak secrets; the backend holds DB credentials and API tokens), can be PR'd by different people, and Pages' bandwidth is free where origin bandwidth is not. The Worker is ~20 lines, far inside the free tier. We chose **`api.mdfly.dev` over `mdfly.dev/api/v1/*`** because mixing cache-everything and never-cache rules on one host is fragile, because CORS from `app.` to `api.` is one explicit allowlist that browsers handle naturally (a same-origin API would still need Origin checks, since an `Authorization`-bearing surface is a different security domain from HTML), and because `api` in the URL bar tells an operator "machine interface" without ambiguity. We chose to **provision `app.` only at v2** rather than serve a placeholder, because a placeholder is build-deploy-monitor tax for a page nobody visits and NXDOMAIN is the truthful state. We chose the **`_landing/` prefix** over hosting landing assets on `cdn.` because same-origin assets keep the Pages pipeline single-step, and `_` is already blocklisted so the slug namespace stays collision-proof. We chose **code-generating the Worker's route table** from the reserved-words list because drift between two hand-maintained parallel lists — a path added to landing but not reserved, or a slug minted by a stale blocklist — is a bug class that should be impossible by construction rather than caught in review. We chose **www→apex via Bulk Redirect, not the Worker**, because the logic is too trivial to spend an invocation on. We chose **blanket noindex** because the anonymous slug space depends on obscurity and a user who shares a sensitive URL should not have a search engine amplify the leak; owned-slug users wanting SEO can publish elsewhere, and this can soften later with a per-Document opt-in. The costs we accept: Cloudflare is on the hot path for apex and `cdn.`, so a Cloudflare outage is a full outage (accepted; multi-CDN is preposterous here); the apex is no longer single-origin, so "slug renders but landing 500s" means checking three origins instead of one, offset by host-based blame; the Worker adds ~1–3 ms to every apex request and is JavaScript in an otherwise-Go codebase, accepted as a tiny bounded interface; Bot Fight Mode is a known false-positive risk on `/llm/*`, where legitimate agent and `curl` traffic looks bot-shaped — v1 ships defaults and the carve-out is one custom rule if telemetry shows blocks; the Purge API needs an API token in backend env, one more secret to rotate; and a 15-year cert renewal is long enough that the procedure will need re-learning, so it gets a runbook. Note that the full marketing content lands with `apps/landing/` at v1.5 (ADR-0014) — v1's Pages deploy carries the legal and abuse pages, and the routing split ships with it rather than being retrofitted later.
