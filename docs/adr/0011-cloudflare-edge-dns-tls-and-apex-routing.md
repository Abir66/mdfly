# Edge: Cloudflare registrar + DNS + proxy, subdomain split, apex served by Caddy (landing files, else backend)

`mdfly.dev` is registered at **Cloudflare Registrar** (at-cost renewal) with **Cloudflare as authoritative DNS**, so the proxy, the R2 custom-domain connector, edge cache, WAF, and Universal SSL all live in one dashboard. Five hosts, each with its own origin and cache posture:

- **`mdfly.dev`** (apex, proxied) is served by the origin's **Caddy**, which dispatches by file existence. The **static landing site** (`apps/landing/`, an Astro build to `apps/landing/dist/`) is bind-mounted read-only into Caddy, and any request whose path resolves to a file there (`{path}`, then `{path}.html`; `/` is `index.html`) is served by `file_server` — `/`, `/docs`, `/_astro/*`, `/robots.txt`, `/og-image.png`. `/index`, `/404` and `*.html` are excluded so the landing never shadows a slug or duplicates a URL. The **Go backend** gets everything else: the slug catchall `/<slug>[/<key>]` and the LLM twin `/llm/<slug>[/<path>.md]` (ADR-0010), the Viewer's `/_static/*` bundle, the OAuth chooser `/cli/login` (ADR-0007), `/install.sh`, and `/healthz`. There is no path list to maintain: slugs cannot contain dots and `docs` is a reserved word, so a landing file cannot collide with a slug.
- **`api.mdfly.dev/v1/*`** goes straight to the backend with **blanket cache-bypass**. This is the CLI's compiled default (`MDFLY_API`). CORS allowlists `https://app.mdfly.dev` and the local dev origin; CLI requests carry no `Origin` and are unaffected.
- **`storage.mdfly.dev/*`** is the R2 bucket via Cloudflare's native **custom-domain connector** (not S3-compat presigned GETs), caching forever from the PUT-time `immutable` header, never touching the backend. A **CORS rule allows the `https://mdfly.dev` origin** so the Viewer's Raw toggle can `fetch()` the source blob.
- **`www.mdfly.dev`** 301s to the apex via Cloudflare Bulk Redirect — no backend involvement.
- **`app.mdfly.dev`** is reserved for the v2 dashboard and is **DNS-unprovisioned in v1** (NXDOMAIN).

The apex is a **proxied A record to the origin VM's reserved static IP** (ADR-0003). Cloudflare terminates TLS at the edge; the origin terminates again with a **Cloudflare Origin CA cert** (15-year, trusted only by Cloudflare) under SSL/TLS mode **Full (strict)**, so learning the origin IP buys an attacker nothing. The origin terminator is **Caddy**, a sibling container beside the Go process (ADR-0003) and the only one there publishing a host port; because it is now the process's TCP peer, it also **strips `CF-Connecting-IP` from any request whose own peer is outside Cloudflare's published ranges**, which is the edge-side half of the rate-limit subject's trust chain (ADR-0013). **Cache rules** per host: apex slug and LLM routes cache-everything respecting the backend's `max-age=300, s-maxage=86400`; `/_static/*` caches on its content hash; landing `/_astro/*` is content-hashed and served `public, max-age=31536000, immutable`, while landing HTML sets no `Cache-Control` and so bypasses the edge cache; `api.` bypasses entirely; `storage.` caches forever. Tier-Cache is on to compress edge-miss fan-out through one upper tier. **Invalidation on commit and delete** is durable, not lazy — see ADR-0012. **Security posture** ships Cloudflare-defensive defaults: Bot Fight Mode on, Security Level Medium, Managed Challenge for borderline traffic, free WAF Managed Rules on, Always-Use-HTTPS, HTTP/3 and 0-RTT on, min TLS 1.2, plus an edge rate-limit per IP on the `/v1/publish/*` and `/v1/update/*` paths as L1 beneath the app limiter (ADR-0013) — its parameters are whatever the plan allows, which on Free is one rule counting IPs over a 10-second window with a 10-second block, matched on path alone because the hostname field is not available at that tier. **HSTS is deliberately off in v1** — it sticky-bricks the domain if HTTP is ever served; enable after one to two months of stable HTTPS-only operation. **Email DNS** advertises null-MX (`MX 0 "."`, RFC 7505), `SPF v=spf1 -all`, and `DMARC p=reject`, since there is no transactional email to send and spammers probe new domains. **Indexing**: every user Document is noindex — `robots.txt` comes from the landing build as an allowlist (`Allow:` for `/`, `/docs`, `/_astro/` and `/og-image.png`, then `Disallow: /`, plus the sitemap; the landing build check fails if a sitemap page lacks an `Allow`), with the Go backend's blanket `Disallow: /` answering when the landing is not built and on `api.mdfly.dev`, and every slug and LLM response carries `X-Robots-Tag: noindex, nofollow` so the header catches crawlers that ignore the file.

We chose **Cloudflare for registrar, DNS, proxy, R2 connector, WAF, and cache** rather than splitting vendors because every one of those is free at this scale, and the alternatives add a second vendor for zero dollars saved and a worse R2 story (the custom-domain connector is Cloudflare-native by definition). We chose the **orange cloud on the apex** over DNS-only because ADR-0010's view path explicitly relies on `s-maxage=86400` to keep the backend off the per-view hot path, with DDoS absorption and origin-IP hiding as bonuses. We chose **R2 custom-domain over presigned GETs** because public Documents (ADR-0001) gain nothing from presigning — the URL is already unguessable via slug plus content hash — and presigning puts CPU per request on a backend that should never see asset traffic. We chose **Origin CA over Let's Encrypt** because the cert is Cloudflare-only-trusted (rejecting anyone who bypasses the edge to hit the origin), valid 15 years with no renewal cron, and free, where Let's Encrypt is a 90-day renewal plus challenge wiring for a single client. Full (strict) is non-negotiable: "Flexible" sends plaintext to origin, making Cloudflare itself the MITM, and plain "Full" accepts a self-signed origin cert. We chose **Caddy serving the landing build at the apex** over a Cloudflare Worker plus Pages, and over embedding the site in the backend binary: Caddy is already the origin terminator, so file-existence dispatch needs no new component, no JavaScript in an otherwise-Go codebase, and no second deploy pipeline, while the landing still ships without a backend redeploy or container restart. The operator runs `git pull` and `npm ci && npm run build` in `apps/landing` on the box. Caddy mounts the parent `apps/landing`, not `dist/`, because a rebuild replaces `dist/` and a direct mount would go stale. We chose **`api.mdfly.dev` over `mdfly.dev/api/v1/*`** because mixing cache-everything and never-cache rules on one host is fragile, because CORS from `app.` to `api.` is one explicit allowlist that browsers handle naturally (a same-origin API would still need Origin checks, since an `Authorization`-bearing surface is a different security domain from HTML), and because `api` in the URL bar tells an operator "machine interface" without ambiguity. We chose to **provision `app.` only at v2** rather than serve a placeholder, because a placeholder is build-deploy-monitor tax for a page nobody visits and NXDOMAIN is the truthful state. We chose **www→apex via Bulk Redirect** because the logic is too trivial to involve the origin. We chose **blanket noindex** because the anonymous slug space depends on obscurity and a user who shares a sensitive URL should not have a search engine amplify the leak; owned-slug users wanting SEO can publish elsewhere, and this can soften later with a per-Document opt-in. The costs we accept: Cloudflare is on the hot path for apex and `storage.`, so a Cloudflare outage is a full outage (accepted; multi-CDN is preposterous here); Bot Fight Mode is a known false-positive risk on `/llm/*`, where legitimate agent and `curl` traffic looks bot-shaped — v1 ships defaults and the carve-out is one custom rule if telemetry shows blocks; the Purge API needs an API token in backend env, one more secret to rotate; and a 15-year cert renewal is long enough that the procedure will need re-learning, so it gets a runbook. This reverses the earlier Worker-plus-Pages apex: the costs of the Caddy approach are that landing deploys are manual on-box builds, `deploy.sh rollback` does not cover the landing (roll back by checking out an older commit and rebuilding), Node LTS (via nvm) lives on the box (an exception to ADR-0015's "nothing is compiled on the box", scoped to the static site), and a Caddyfile change needs a one-time `docker compose up -d caddy`. The full marketing content lands with `apps/landing/` at v1.5 (ADR-0014).
