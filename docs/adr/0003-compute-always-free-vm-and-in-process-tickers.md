# Backend compute: an always-on free-tier VM, periodic work as in-process tickers

The Go backend runs on a single **always-on ARM VM from a free tier that does not scale to zero and has no CPU-minute cap** (Oracle Cloud Always Free at the time of writing). The hard constraint driving this is free-tier-only — no spend. Because the process is never suspended, **all periodic work runs as in-process goroutines on `time.Ticker`**, started at boot with no external scheduler: the CDN purge-queue drain every ~15 minutes (ADR-0012) and the document lifecycle GC hourly (ADR-0005). Four **portability constraints** are held so the box stays swappable to any other host later: stateless processes (no on-disk state between requests), configuration by environment variables only (no config files, no platform-specific secret APIs), one portable `Dockerfile`, and a generic `/healthz` endpoint. No host-specific feature — managed jobs, platform service discovery, proprietary secret stores — may be relied on.

We chose always-on-free over free-but-suspending options (a 60-CPU-minute/day capped app tier, or any scale-to-zero PaaS): a suspended process cannot run an in-process ticker, which would force every job behind an external trigger chain (edge cron → worker → an authenticated internal endpoint) and forbid fire-and-forget goroutines entirely, since anything spawned after a response returns is untracked by the platform and can be killed on idle-unload. Always-on erases both problems — tickers just run, and a detached goroutine survives to the next reboot. Job **correctness does not depend on always-on**: the durable `purge_queue` (ADR-0012) and the DB-tracked lifecycle GC (ADR-0005) both survive reboots regardless, so always-on buys the removal of the external-trigger tax, not the correctness. The honest costs we accept: we own OS patching, origin TLS, the deploy pipeline, monitoring, and backups, where a managed platform would have owned them; free-tier providers reclaim *idle* instances, so the tickers plus real traffic must keep the box above the idle threshold; ARM capacity in free tiers is scarce at provision time, so standing the VM up may need a retry loop; and a single box means a host outage is a full outage, accepted at this stage because the alternative costs money and the portability constraints make a move cheap if that trade ever flips.
