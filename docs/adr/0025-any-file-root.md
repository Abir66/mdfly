# Any file type may be a Document Root, not just markdown

A Document's [[Root]] may be a file of any type — markdown, text/code, or binary (PDF, image, archive, …) — rather than being restricted to a single `.md` file. `mdfly publish report.pdf` and `mdfly publish main.go` are first-class, producing the same slug/URL/tracking machinery as a markdown publish. The CLI sends no `root_kind` signal on the wire: the server already resolves presentation purely from the addressed key's extension plus a binary content-sniff (`internal/server/service/view` — markdown → SSR HTML, text/code ≤ `PreviewMaxBytes` and non-binary → chroma-highlighted source, everything else → a download card). Markdown stays the product's center of gravity (default for [[Text Publish]], the only type with a meaningful [[LLM Path]] twin), but it is no longer a gate. The `-r` walk applies only to a **markdown** Root; a non-markdown Root (text, code, or binary) has no markdown links to follow, so its Bundle is a single blob with no walk.

We chose this over keeping a hard "markdown-only Root" guard because the guard bought nothing: the [[Viewer]]'s center dispatch and the server's render path already handled non-markdown nodes (they had to — assets inside a bundle are viewed the same way), so allowing them at the Root position is near-zero incremental cost and removes an arbitrary rejection users would hit immediately ("why can't I just share this PDF?"). The trade-off we accept is that the LLM twin degenerates for non-text Roots — an agent hitting `/llm/<slug>` for a binary gets a short "download at <url>" stub, not useful markdown — which mildly dilutes the "every Document has a clean agent-readable twin" story. We judged that acceptable: the twin remains fully meaningful for the markdown/text Roots that dominate real use, and a degenerate-but-honest stub beats refusing the publish outright. The reversal cost is low (re-adding a guard is trivial), but the product-identity shift from "markdown sharing" toward "share any file, markdown gets special treatment" is real and worth recording.
