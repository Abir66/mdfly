# Multi-provider identity via loopback OAuth, no mdfly-owned handle

Supersedes ADR-0003. Identity in mdfly is provider-agnostic and OAuth-based: GitHub at v1 launch, Google to follow, additional OAuth providers (Apple, Microsoft, GitLab, etc.) addable without schema change. The data model splits identity from user — `users (id, display_name, primary_email, created_at)` is the canonical mdfly account, and `identities (user_id, provider, provider_id, email, primary key (provider, provider_id))` is a join table where each authenticated provider login is one row pointing at one `users` row. There is **no mdfly-minted handle**: URLs are `mdfly.dev/<slug>` (ADR-0010 flat namespace), document attribution renders `display_name` from the provider, and no profile pages exist in v1 — so no globally-unique user-chosen identifier is needed. Account linking is **explicit only** (`mdfly link --provider <name>` from an authenticated session attaches a second `identities` row to the current `users` row); matching by email across providers is never automatic, and a link attempt that hits an `identities` row already attached to a different `user_id` is rejected with 409. The primary login flow is **loopback OAuth code flow** (RFC 8252) modelled on `claude login` / `gh auth login --web` / `gcloud auth login`: `mdfly login` binds a localhost HTTP server on an OS-assigned ephemeral port, opens the user's browser to `mdfly.dev/cli/login?port=<p>&state=<csrf>`, the user picks a provider on the mdfly-hosted chooser page, completes OAuth in-browser, the backend redirects to `http://127.0.0.1:<p>/callback?code=<mfxc_...>&state=<csrf>` carrying a single-use 60-second exchange code, the CLI's local server captures the code, the CLI POSTs it to `/api/auth/cli/exchange` to receive the real session token `mfst_<32B base64url>`, and the browser tab shows a "you can close this" success page (auto-closes if the browser permits). The session token is the same shape and same DB row whether the client is CLI or browser: `sessions (id, token_hash, user_id, client_kind, device_label, created_at, last_seen_at, revoked_at)`, hashed as `SHA256(mfst_<rand>)`, with `client_kind ∈ {'cli', 'browser'}` so the table serves both surfaces. For headless environments without a browser (SSH, Docker, CI), `mdfly login --device` falls back to OAuth device flow against the same provider endpoints, terminating in the same `sessions` insert. A planned v2 dashboard at `mdfly.dev/dashboard` will reuse the same backend OAuth code flow with cookie-based session delivery (`HttpOnly`, `Secure`, `SameSite=Lax`); writes against the API always require the token in the `Authorization` header even when a session cookie is present, eliminating CSRF surface on state-changing endpoints.

We chose this over (a) **staying GH-only** (the original ADR-0003 position): closing the door on non-GitHub users is a permanent product-shape choice we don't want to lock in this early, even though the immediate v1 audience is dev-leaning; adding a second provider after launch requires either ugly nullable columns (`users.github_id?`, `users.google_id?`) or a painful migration to the join-table layout, so paying that migration cost now while there are zero rows is free. We chose this over (b) **multi-provider with a mdfly-owned handle**: handles only earn their cost when they appear in URLs or `@mentions`, neither of which exist in v1, and minting a handle namespace immediately invites reserved-word collisions with the slug namespace, uniqueness arbitration UX, rename policy, and squatting fights — all to drive zero v1 features. We chose this over (c) **auto-link-by-email across providers**: same-email auto-linking is a known account-takeover footgun (attacker controls one provider's verified email and claims the other's account on first login); industry default is explicit-link-while-authenticated, and "your two accounts are separate until you link them" is recoverable while "we silently merged your accounts" is not. We chose **loopback callback as the primary CLI flow** over (d) **OAuth device flow as primary**: device flow's `user_code` + verification URI is a worse UX than "click the GitHub button you already know" (everyone hates retyping codes), and Claude Code / `gh` / `gcloud` have already normalized loopback as the expected CLI auth pattern. Device flow is retained behind `--device` because it's the only flow that works in headless environments. We chose **a mdfly-hosted provider chooser page** at `/cli/login` over (e) **forcing `mdfly login --provider <name>`**: a default invocation should Just Work and let the user pick a provider visually, especially during signup when they may not have decided yet; the explicit `--provider github` flag remains for power users and scripts. We chose **exchange-code indirection** (browser redirect carries short-lived `mfxc_` code; CLI exchanges via POST for `mfst_`) over (f) **token-in-redirect**: putting the real session token in a URL leaks it into browser history, system access logs, and the URL bar; the OAuth code-flow indirection pattern exists precisely to avoid that, and the 60s single-use TTL on `mfxc_` makes log-leaked codes worthless. We chose **DIY identity** over (g) **Clerk / Auth0 / WorkOS**: hosted identity providers optimize for browser SPA flows, hosted sign-in UIs, password resets, and MFA — none of which mdfly uses; their CLI device-flow support is shaky and their default session-token lifetimes (60s JWT in Clerk's case) are a hard mismatch for long-lived CLI bearer tokens stored in a credentials file; vendor lock-in on identity is forever-painful to unwind and the DIY footprint here is one OAuth proxy per provider plus three tables, well under the cost of a hosted-provider escape hatch. The cost we accept: identity is now a real subsystem with provider abstraction, per-provider OAuth-app configuration in deploy env, explicit link/unlink CLI commands, headless-env fallback flag, and a transient `exchange_codes` table to GC; the v1 footprint is larger than the strict GH-only-device-flow minimum, paid in exchange for matching the auth UX users already know from Claude Code and `gh`, and for a v2 dashboard that doesn't require an auth rewrite.
