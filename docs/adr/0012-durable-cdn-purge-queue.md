# Durable CDN purge queue with transactional enqueue and ticker-driven retry

Cache invalidation on publish, update, and delete is backed by a durable **`purge_queue(slug PRIMARY KEY, enqueued_at, attempts, next_attempt_at)`** table, deduplicated by slug (ADR-0005). The slug is **enqueued in the same transaction as the row flip**, so a committed write can never be left un-enqueued. Immediately after commit a best-effort goroutine attempts the purge inline — pure latency optimization, safe to lose — and an **in-process ticker every ~15 minutes** (ADR-0003) drains the queue with backoff via `next_attempt_at`, deleting a row on success. Purge is **by prefix**: two prefixes per slug, `mdfly.dev/<slug>` and `mdfly.dev/llm/<slug>`, each covering the bare page and every sub-path in one operation. This fits Cloudflare's Free-plan purge limits — 5 requests/minute (token bucket, burst 25) and **30 prefixes per request**, which is prefix purge's own cap below the general 100-operation ceiling, so 15 slugs per call at two prefixes each. Purge is idempotent and always re-reads current DB state, so a late or duplicated drain is harmless. Purge success is **not a commit precondition**: worst case is a stale viewer for up to the 24-hour `s-maxage` (ADR-0011).

We chose a **durable DB queue** over an in-goroutine retry (the original design) because a failed purge on update or delete is not acceptable: a goroutine's retry state dies with the process on reboot, crash, or deploy, silently stranding stale content until the TTL expires, whereas a queue row survives and the drain ticker retries across restarts. We chose to **enqueue transactionally and treat the inline attempt as pure fast-path**, rather than "try inline, enqueue only on failure", so there is no window in which a write commits but its purge intent is lost — the immediate goroutine can be killed at any moment without consequence. We chose **prefix purge** over enumerating individual URLs because one prefix covers a slug's bare page and all sub-paths in a single operation (collapsing an earlier four-URL-pattern scheme to two prefixes), halving the prefix cost per slug and turning the 30-prefix cap and 5-req/min limit into roughly 75 slugs/minute of headroom. We chose **Postgres, not the Redis instance already in play for rate limiting (ADR-0013)**, because the queue needs durability and a transactional enqueue inside the same transaction as the row flip; Postgres gives both, while Redis at our tier is best-effort and eviction-prone and gives neither. The residual race we accept: a read landing in the millisecond window between the purge firing and the DB flip committing can repopulate stale cache — backstopped by `s-maxage` and closable, if it ever matters, by a delayed second drain.
