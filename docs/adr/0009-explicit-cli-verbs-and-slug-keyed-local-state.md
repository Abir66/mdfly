# CLI: explicit `publish` / `update` verbs over slug-keyed local state

The CLI splits create-versus-modify intent into **two always-explicit verbs**. `mdfly publish <file>` always mints a fresh slug and creates a brand-new Document — repeated invocations on the same file produce independent URLs and one new record each. `mdfly update <file>` modifies an existing Document in place. There is **no bare-command shortcut** (`mdfly <file>` with no verb) and no `--new` flag: `publish` *is* the new-URL verb. `--force` exists only on `update`, where it bypasses the optimistic `parent_manifest_hash` check (ADR-0006). Local state is `~/.mdfly/state.json`, **keyed by slug** — the server-authoritative, immutable identifier — with one record per Document carrying `slug`, `url`, `manifest_hash`, `tier`, `size`, `file_count`, `created_at`, `updated_at`, `source` (`file` | `text`), and `path` (the absolute source path, or `null` for a Text Publish). The `path → slugs` relationship that `mdfly update <file>` needs is a **derived secondary index** built at load time, not the primary key. Disambiguation on `update <file>`: zero mapped slugs errors out with a hint to publish first or pass `--slug`; one targets it; two-or-more pops an interactive picker on a TTY, or errors demanding `--slug` in non-TTY contexts like CI. `--slug <s>` is the explicit escape hatch for non-interactive targeting and for recovery after local-state loss (file moved, `~/.mdfly` wiped, new machine, or a Text Publish which has no path at all). Edit Tokens live separately in `~/.mdfly/credentials` (ADR-0008); a state record only notes that a token exists. Volatile data — the once-per-24h release check — lives in a separate `~/.mdfly/cache.json` so a corrupt cache can never clobber durable publish tracking. Records **self-heal**: a `404`/`410` from the server on update or delete prunes the stale entry and tells the user.

We chose two explicit verbs over **a single `publish` that auto-detects "have I seen this file before?"** because that pattern silently overwrites Documents whenever the user's mental model diverges from the CLI's heuristic — the user thought they were sharing a fresh copy, the CLI updated an old one because local state still had the mapping — and a wrong guess on a destructive operation costs real bytes that optimistic concurrency cannot save (the `parent_manifest_hash` will be perfectly correct, because the CLI did just fetch it). Explicit verbs make intent legible from a shell history or CI log. We chose them over **`publish --new` / `publish --update`** because that is the same information density at a uglier call site while making the safe default ambiguous. The bare-command shortcut was specified in an earlier draft (0 mapped slugs → publish, 1 → update, 2+ → disambiguate) and dropped for the same reason: a first positional treated as "file if it exists on disk, else verb" is another on-disk heuristic whose wrong guess routes a destructive `update`, and `publish`/`update` were always the canonical scriptable forms anyway — legibility beats saved keystrokes. We chose **slug-keying over path-keying** because the slug is the only stable identity in the system: a user who renames or moves `notes.md` after publishing has not changed the Document, yet a path-keyed map would silently orphan the record — `mdfly list` would show a dead path and `mdfly update` would think the file was never published and mint a new URL. Under slug-keying the record survives untouched; only its `path` goes stale, and it re-attaches with `--slug`. The costs we accept: users iterating on a draft must learn two verbs instead of one (they needed both anyway — publish-once-then-iterate *is* the iterate pattern, so "type `update` to update" is a one-time cost in exchange for never silently overwriting); file-oriented lookups are a scan of the derived index rather than an O(1) map hit; and one file legitimately maps to many slugs, so `update <file>` must disambiguate — which is the behavior the explicit-verb model already required, so slug-keying adds no new UX surface, only a more durable substrate.
