# App-level identity-aware rate limiting on Upstash Redis

The backend adds a second rate-limiting layer (L2) in front of the write paths — `publish/init`, `update/init`, and `DELETE /documents/:slug` — beneath the Cloudflare edge rate-limit (L1, ADR-0021, 10 req/min per IP, IP-only). L2 is **identity-aware**: the key is the Edit Token on update/delete (the request already carries `Authorization: Bearer mftk_...`) and falls back to the caller's `CF-Connecting-IP` for anonymous publish (trusted only from Cloudflare's published IP ranges, since `RemoteAddr` behind the proxy is a Cloudflare edge IP, not the client). The store is **Upstash Redis** (serverless HTTPS REST). Counting is fixed-window via one house method — `incrementWithTtl(key, ttl)` doing a pipelined `INCR` + `EXPIRE` on every call — where the key embeds a time-bucket step (`floor(now/window)`) so each window is a fresh key that self-resets. Two windows per subject: **10/min** and **30/hr**. On any Redis error the limiter **fails open** (allow the request). Read paths (SSR HTML, `/llm` twin, `cdn.mdfly.dev`) are never limited — they are served from edge cache and never touch the backend hot path.

We chose **Upstash** over an in-process limiter because the limiter state must survive process restarts and be shared if the backend is ever scaled past one instance; Upstash's serverless HTTPS REST model needs no persistent connection, is free at our scale, and adds no ops. We chose **fixed-window with a time-bucketed key** over token-bucket or sliding-window because it collapses to a single `INCR`+`EXPIRE` with no read-modify-write and no Lua: the bucketed key makes the window self-resetting, so the `EXPIRE` exists only to garbage-collect dead keys — a missed `EXPIRE` leaks one stale key (memory), it can never permanently block a subject, because the next window is a different key. We chose **fail-open** over fail-closed because rate limiting is abuse mitigation, not a correctness invariant; a Redis outage must degrade to "unthrottled" (L1 at the edge still stands), never to "all writes blocked." We chose an **identity key with IP fallback** because an Edit Token identifies the actual editor across IPs, while anonymous publish has no identity to key on and IP is the only signal available — with the `CF-Connecting-IP` caveat that the real client IP must be read from the Cloudflare header, not the TCP peer.
