# Separate `publish` and `update` verbs in the CLI

> **Amended 2026-07-17.** Two reversals from the original: (1) the state file is now **slug-keyed**, not path-keyed — `state.json` holds one record per slug with `path` as a derived secondary index (see the new ADR on slug-keyed local state and [[Local State]] in CONTEXT.md); the `path → [slug, ...]` shape below is superseded. (2) The bare-command shortcut (`mdfly <file>` with no verb) is **dropped** — the verb is always explicit. ¶2 is retained only to record why. The core decision (two explicit verbs) is unchanged and reinforced.

mdfly's CLI splits the create-vs-modify intent into two distinct verbs. `mdfly publish <file>` always mints a fresh slug and creates a brand-new Document — repeated invocations on the same file produce independent URLs, recording one new slug-keyed entry per call in `~/.mdfly/state.json` (a path → slugs view is derived from those records). `mdfly update <file>` modifies an existing Document in place; it disambiguates by consulting the derived path → slugs view — zero entries errors out with a hint to publish first, one entry targets that slug, two-or-more pops an interactive picker on a TTY (or errors with a `--slug` hint in non-TTY contexts like CI). The `--slug <s>` flag is supported on `update` for explicit non-interactive targeting and to recover after a local-state loss (file moved, `~/.mdfly` wiped, new machine). The `--force` flag remains on `update` only — it bypasses the optimistic `parent_manifest_hash` check (ADR-0012). There is no `--new` flag because `publish` itself is the new-URL verb.

**Superseded (see amendment above).** A bare-command shortcut `mdfly <file>` (no verb) was originally specified: 0 mapped slugs → `publish`, 1 → `update`, 2+ → disambiguate. It is dropped in favor of always-explicit verbs. The reasoning that killed it is the same reasoning in ¶3 against auto-detect: a first positional treated as "file if it exists on disk, else verb" is another on-disk heuristic whose wrong guess routes a destructive `update` — legibility of intent wins over saved keystrokes, and `publish`/`update` were always the canonical scriptable forms anyway.

We chose this over (a) a single `publish` verb that auto-detects "have I seen this file before?" and switches between create and update on its own: that pattern silently overwrites Documents whenever a user's mental model diverges from the CLI's heuristic (e.g. the user thought they were sharing a fresh copy but the CLI updated an old one because `~/.mdfly/state.json` still had the mapping). A wrong guess on a destructive operation costs the user real bytes, and the optimistic-concurrency check from ADR-0012 doesn't catch this — `parent_manifest_hash` will be correct because the CLI did just fetch it. The explicit-verb model makes the intent legible from the command itself: anyone reading `mdfly publish report.md` in a shell history or CI log knows a new URL was minted; `mdfly update report.md` makes the in-place modification obvious. We chose this over (b) a single `publish` verb with required `--new` / `--update` flags: that's the same information density as two verbs but uglier at the call site, and it makes the safe default ambiguous. The cost we accept: users iterating on a draft must learn two verbs instead of one — but they were going to need both anyway (publish-once-then-iterate is the iterate pattern), and "type `update` to update" is a one-time learning cost in exchange for never silently overwriting a Document.
