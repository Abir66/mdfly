# View path: backend-served shell with inlined Bundle Manifest, SPA fetches blobs directly from R2

**Superseded by ADR-0018.** The decision below was reversed: the Manifest is no longer inlined into the shell, the SPA is gone, and the backend now SSRs HTML directly (with a parallel `/llm/` raw-markdown twin for AI agents). Storage layout from ADR-0001 is unchanged; only the view-time consumer of the Manifest moves from client to server. Retained here for the original reasoning trail.


When a viewer hits `mdfly.dev/<slug>`, the Go backend serves a small HTML shell containing: the React SPA bootstrap, pre-rendered `<meta>` OpenGraph tags, the correct HTTP status (`200` for live, `410` for deleted/expired, `404` for never-existed), and the Bundle Manifest inlined as a JSON `<script>` tag. Once loaded, the SPA reads the inlined Manifest, resolves each logical path to its content hash, and fetches every Bundle blob (markdown and assets) directly from R2 via the `cdn.mdfly.dev` Cloudflare custom domain at `<hash>.<ext>` URLs — the Go backend is **not** on the per-asset fetch hot path.

We chose this hybrid over a pure-CDN view path (which would lose the `410` vs `404` HTTP distinction and the ability to suppress shells for deleted Documents) and over a backend-proxied view path (which would CDN-cache poorly and force every viewer hit to pay the Go server's latency). Inlining the Manifest into the shell costs the backend a per-viewer Postgres read of `documents.bundle_manifest`, which is mitigated by a Redis cache keyed on `(slug, manifest_hash)`; in exchange the SPA needs zero extra fetches to start resolving links. Cache invalidation simplifies meaningfully compared to a non-content-addressed layout: because every R2 URL ends in a content hash, the CDN's Bundle cache is **immutable forever** and never needs busting — only the shell HTML (which is the one mutable URL in the view path) must invalidate on Update, handled via short TTL plus the backend's own Redis cache invalidation.
