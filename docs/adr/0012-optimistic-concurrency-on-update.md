# Optimistic concurrency on Update via parent manifest hash

Every Document row carries a `manifest_hash` column — the SHA256 of the canonical JSON-serialized Bundle Manifest currently bound to that slug. The Publish `init` response includes this value (or `null` for a new slug); the Publish `commit` request echoes it back as `parent_manifest_hash`. On commit, the server runs the row update in a single transaction guarded by `WHERE slug = $1 AND manifest_hash IS NOT DISTINCT FROM $2` — if the row's current `manifest_hash` no longer matches what the CLI started from, the update affects zero rows and the server responds **409 Conflict** with the current server-side manifest. The CLI surfaces this to the user as: `Conflict: 'notes' updated elsewhere since you started. Re-run to retry, or pass --force to overwrite.` A `--force` flag, available from day one, skips the `parent_manifest_hash` check (sends `null` or omits the field) and unconditionally replaces the manifest. First-Publish races where two CLIs race to claim the same slug are handled by the existing UNIQUE constraint on `slug`, which produces a distinct error path (`slug taken`) rather than 409.

We chose this over (a) last-writer-wins silent overwrite: with no version history (per ADR-0002), an LWW collision destroys the loser's bytes invisibly — the user sees "Publish OK" but their work is gone 200 ms later, and recovery requires re-running on the original machine while bytes still exist locally. Optimistic conflict detection raises a loud, actionable error instead. We chose this over (b) pessimistic per-slug advisory locking acquired at `init` and released at `commit`: cheap when uncontended, but a CLI that crashes between `init` and `commit` (or one that runs `mdfly preview` and never publishes) strands the lock until expiry, and lock-leak operations are exactly the kind of cost we avoid by keeping the backend stateless (ADR-0007). The cost we accept: a `manifest_hash` column and a single conditional update, plus CLI logic to render 409 well and a `--force` escape hatch — small surface area for the integrity guarantee. The `--force` flag is provided day-one because v1 has no `mdfly pull` command; without `--force`, a user staring at a 409 with no escape would be stuck.
