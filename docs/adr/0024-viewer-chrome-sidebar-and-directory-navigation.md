# Viewer chrome: sidebar file-tree + directory navigation, extensions kept in URLs, static assets

**Amends ADR-0018 (view-path URL convention, resolution-pipeline scope, stylesheet delivery) and ADR-0021 (R2 CORS) in place. Supersedes S19 (inline viewer CSS).**

The human view path graduates from a single SSR'd document page to a **Viewer chrome**: a collapsible left **file-tree sidebar** listing the whole Bundle, a **center** column that dispatches on the type of the addressed node, and a **breadcrumb** of the logical path atop the center. The tree is built **synthetically** from [[Bundle Manifest]] keys — a directory is any path prefix shared by one or more keys, so a folder "exists" only if it contains an uploaded file (no manifest/schema/wire change; folders are never stored). Every node — markdown, asset, or directory — is addressed at `mdfly.dev/<slug>/<key>` by its **exact manifest key, extension included** (`docs/api/auth.md`, `assets/logo.png`); this **reverses ADR-0018's strip-`.md` convention** (and the S11 cross-md rewrite that implemented it) in favor of a uniform "every tree node maps to `/<slug>/<exact-key>`" rule. Resolution is: exact key → serve that file in chrome; else a path that is a directory prefix → a Directory Listing; else 404 (trailing slashes optional, 301-canonicalized). Center dispatch by type: markdown renders to HTML with a **Raw toggle** (top-right) that lazy-fetches the byte-identical source blob directly from `cdn.mdfly.dev` **once**, caches it client-side, and swaps it in via CSS; an image shows inline; a text/code file ≤ `PreviewMaxBytes` (1 MB, decided from the manifest `size` with **no blob fetch** above the cap) and verified non-binary (valid UTF-8, no NUL bytes, sniffed **after** fetch to defend against a lying extension) renders as **server-side chroma-highlighted** source (zero client JS — chroma already highlights fenced code in the markdown path); an oversize, binary, or otherwise-unrecognized file becomes a metadata card with a Download link to the CDN blob; a directory becomes a listing (folders first, then files with sizes) that **auto-renders a `README.md`, else `index.md`, below it** by reusing the existing markdown render path. [[Root]]'s `root_path` becomes **nullable** in the data model — an empty root means a folder-Document whose bare URL serves a root Directory Listing — as forward-compat for a future `mdfly publish <folder> --root <dir>`; the v1 CLI never produces this, so it ships as server-side tolerance plus a fixture test. The sidebar uses native `<details>`/`<summary>` so folder collapse needs **zero JS**; the server emits `open` on the current file's ancestors (auto-expand) and `aria-current` (highlight). Collapsing the whole sidebar leaves a thin rail (Claude/ChatGPT style) whose state persists in `localStorage` and is applied by a tiny inline `<head>` snippet before paint (the one state that *must* survive full-reload navigation, or the rail re-expands on every click); per-folder `<details>` state is allowed to reset to the server default each load. Under a 768 px breakpoint the sidebar becomes a drawer behind a mobile-only top bar (`☰` + wordmark); on desktop there is no global top bar (the sidebar owns its `[mdFly ☰]` header, the breadcrumb lives atop the center). The Viewer's CSS and JS ship as **content-hashed external static assets** under the reserved `/_static/*` path (Worker-routed to the backend, `Cache-Control: immutable`), **not** inlined per S19 — fetched once and reused across every full-reload navigation. The Raw toggle's cross-origin fetch from `cdn.mdfly.dev` requires an **R2 CORS rule** allowing the `https://mdfly.dev` origin (the ADR-0021 amendment). `landing` and `static` are added to the [[Reserved Words]] blocklist.

We kept **full-page-reload SSR** (ADR-0018) over a SPA/client-router even though the UI is now multi-page navigation, because the chrome — sidebar tree, breadcrumb, type-dispatched center — is a pure function of `(slug, key, manifest_hash)` and renders once per Update then sits in Cloudflare's `s-maxage=86400` cache; a SPA would add a JS bundle, a blank-flash, router-state bugs, and a duplicate client-side resolution layer to buy soft-navigation that sub-100 ms cached reloads already deliver. We **inline the file-tree into every page** rather than fetching it once as JSON because inlining needs no extra request, no paint flash, and works with JS off, and each page is independently CDN-cached anyway; the cost — the tree's bytes repeat across a Document's pages — is absorbed by gzip and is small even for a 500-file Bundle. We chose **synthetic folders from manifest keys** over a stored directory structure because the CLI uploads no empty directories in v1, so materializing folders would be untested schema weight for no user-visible payoff; the accepted consequence is that a directory listing reflects manifest contents, not the publisher's on-disk tree, which is correct until the recursive-folder-publish walk lands. We **reversed the strip-`.md` URL convention** despite it being shipped (S11) because keeping extensions makes the model uniform — one rule, "tree node → `/<slug>/<exact-key>`", with trivial file-vs-directory disambiguation — and matches the GitHub-style file browser the Viewer imitates; the cost is reworking S11's rewrite plus the ADR-0018/CONTEXT wording, and the breaking of any already-distributed link (none exist — nothing has shipped). We chose **external content-hashed static assets** over S19's single inline `<style>` because the load shape inverted: a single document re-using one inline block is cheap, but browsing twenty pages re-downloads inline CSS/JS twenty times, whereas an `immutable` external bundle is fetched once and reused — strictly better for the multi-page nav the sidebar creates, and it keeps the backend off the hot path entirely (CDN serves `/_static/*`); the cost is one Worker route, two reserved words, and `go:embed`'ing the files. We chose to **fetch the raw blob from the CDN** (embedding its URL, exposing the content hash) over inlining both rendered + raw in the page or proxying a same-origin `?raw=1` route, because inlining doubles every markdown page's payload against the "fast initial render" goal and a backend route puts the server on the raw path; the CDN fetch is zero backend load and the hash leaks nothing (no `project_root`, and embedded assets already expose their hashes), at the cost of one R2 CORS rule and a cross-origin request. We chose **server-side chroma over a client syntax-highlighter** because chroma is already in the Go stack and styled, so highlighting standalone code files adds zero client JS bundle — the user's bundle-size worry simply does not apply. The honest costs we accept: (a) the resolution pipeline now serves non-markdown and directories in chrome, not just markdown, widening ADR-0018's surface; (b) `root_path` nullability ships dormant and only fixture-tested until folder-publish exists; (c) the "Download" affordance cannot force `Content-Disposition: attachment` cross-origin, so some types (PDF) open in-browser rather than save — forcing attachment is deferred; (d) per-folder collapse state resets on navigation (only the whole-sidebar rail persists); and (e) ADR-0018's URL/pipeline/stylesheet description and ADR-0021's CORS posture become stale until amended — handled by the amendment note here and inline edits.
