# R2 blob deletion and document lifecycle GC (`expired` / `abandoned` states, `blobs_deleted_at`)

A single **hourly in-process GC job** (ADR-0029 ticker) drives three terminal document transitions and deletes their R2 blobs. It adds two `documents.status` values via a `TEXT + CHECK` migration (the same one-line pattern as migration `0002`): **`'expired'`** — an anonymous Document past its `expires_at`; serves **410**, exactly like `deleted` — and **`'abandoned'`** — a `pending` row that never committed past a 1-hour grace; serves **404**, because it was never published and no URL ever resolved it. One new column, **`blobs_deleted_at TIMESTAMPTZ`**, records that a row's blobs have been removed. Each pass: (a) flips anon `published` rows past `expires_at` → `expired`; (b) flips `pending` rows older than 1h → `abandoned`; (c) for any row whose state calls for blob removal and whose `blobs_deleted_at IS NULL`, LISTs the `documents/<slug>/` prefix and issues batched `DeleteObjects`, then stamps `blobs_deleted_at`. Blob removal waits a **24-hour grace** for `deleted` and `expired` rows, and is **immediate** for `abandoned`. This covers DELETE, expiry, and abandonment only — cross-Update orphaned-Asset cleanup stays deferred (ADR-0017's accepted leak).

We chose **distinct `'expired'` / `'abandoned'` statuses** over reusing `'deleted'` because the states are observably different — `expired`/`deleted` return 410 while `abandoned` returns 404 — and an operator reading rows must be able to tell "user deleted it" from "anon TTL lapsed" from "init never finished"; collapsing them onto one status throws that signal away and makes every status index mean several things. We chose a **DB-tracked `blobs_deleted_at` flag driven off the `documents` table** over a Redis work-queue because the table already *is* the work-list — ADR-0019 ships partial indexes on `status='pending'` and on `expires_at` — so a second store would only add a sync burden and a drift risk against the source of truth. We chose **LIST + batched `DeleteObjects` on the `documents/<slug>/` prefix** over tracking individual blob keys because blobs are per-slug namespaced (ADR-0001) with no cross-document sharing, so the whole-slug prefix is authoritative and "delete the prefix" is always safe — no refcount, no key ledger. We chose the **24-hour grace** for `deleted`/`expired` to bound the blast radius of a mistaken delete and to let any in-flight edge read drain before the bytes vanish; `abandoned` skips the grace because a never-published row's blobs were never served by any URL.
