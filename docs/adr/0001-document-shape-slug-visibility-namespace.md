# One mutable public Document per slug, in a flat global namespace

A slug is a stable, forever pointer to "the latest Bundle published under it." `mdfly update` replaces the Bundle in place; there is no version history and no `@version` URL form. Every Document lives at `mdfly.dev/<slug>` in a **single flat global namespace** — there is no `/<user>/<slug>` form and the owner's identity never appears in the URL, so Claim does not rewrite anything. Anonymous slugs are 8-char base62, server-generated; Owned slugs are user-chosen `[a-z0-9-]{1,64}` (first-come-first-served against the global namespace) or a random fallback, validated against a reserved-word blocklist (`api`, `cdn`, `login`, `_`, `_static`, `landing`, and the other live/planned top-level routes). A slug is **never reused**: a deleted or expired Document keeps its slug reserved forever and serves `410 Gone`, distinct from `404` for never-existed. Every Document is **public** — no auth-gated, password-protected, or team-restricted mode exists, and "private" sharing is exactly the unguessability of the anonymous slug (62^8 ≈ 2 × 10^14, rate-limited against enumeration per ADR-0013). Assets orphaned by an Update are **not** collected in v1; they remain in R2 as an accepted leak until the deferred cross-Update asset GC (ADR-0014).

We chose mutable-in-place over immutable-per-publish (every update mints a new slug) and over mutable-with-history because the dominant story is "I shared this URL, let me fix the typo" — breaking a shared URL is a worse failure than losing the pre-typo bytes, and a versioned mode can be layered on later behind a flag without changing the default URL contract. Readers needing byte-exact archival snapshot externally. We chose the flat namespace over per-user URLs because these URLs are shared as links, not typed from memory: a memorable branded URL is worth little, while one uniform URL shape is worth a lot (one routing pattern, no rewrite on Claim, and the Anonymous-vs-Owned distinction stops leaking into the URL surface). The costs are real and accepted: squatting is possible (first user to grab `notes` holds it forever, mitigated by the always-available random fallback and by direct DB reclamation if abuse appears), the blocklist must grow whenever a top-level route is added (ADR-0011 code-generates the edge's static-route table from the same list so the two cannot drift), and future profile pages are constrained to a non-root prefix such as `/u/<user>`. We chose public-only over a viewer-side ACL because it keeps the read path a pure function of `(slug, manifest_hash)` that the CDN can absorb entirely (ADR-0010), and link-sharing matches the mental model of a secret gist; the honest cost is that mdfly is unsuitable for content that must not be shared by accident — a forwarded URL *is* a permission grant — and this default will not drift without a superseding ADR.
