# Deploy pipeline: prebuilt images, operator-triggered blue-green swap

Every push to `main` has GitHub Actions **cross-compile the ARM binary, pack it, and publish a private image tagged with the commit SHA** to the repo's GitHub Container Registry, pruning to the newest 10 versions on each run; the box never compiles. Deploys are **operator-initiated**: an SSH session runs `deploy/deploy.sh` — tracked in the repo, not left on the box, because it now holds real logic — which pulls the repo for the things that are not in the image (`deploy/compose.yaml`, the Caddyfile, `migrations/`), pulls the tagged image, and branches. The web tier runs as **two fixed slots, `app_blue` and `app_green`**, both listed permanently in the Caddyfile with active health checks on `/healthz` and retry-onto-the-other-upstream, so Caddy's config is written once and never touched by a deploy; the script starts the idle slot, waits for it to answer `/healthz`, then stops the live one. `/healthz` stays **dependency-free** (`internal/server/handlers/ops.go`) and is deliberately not upgraded to probe Postgres or R2 — a boot already fails without a DB ping, so answering at all implies a healthy boot, whereas a dependency-probing health check would let one database hiccup mark **both** slots dead and turn a degraded site into a dark one. Three timeouts form a chain that must strictly increase: **request ceiling 30s → in-process drain 35s → container SIGKILL grace 45s**, with the jobs container overriding the latter two per-service to ~115s and 120s. **Schema changes bypass the overlap entirely**: the script compares the highest file in `migrations/` against the applied `schema_migrations` version and, on a mismatch, migrates and then plainly recreates the single live slot, accepting ~5 seconds of downtime. Rollback is a **bookmark**: the script records the outgoing tag before swapping, so `deploy.sh rollback` re-swaps to it — valid for code-only deploys only.

We chose **operator-triggered over push-button CI** because the alternative stores an SSH key that opens the production box inside a GitHub account, which contradicts a posture that already refuses to publish Redis's port and admits 443 only from Cloudflare's ranges (ADR-0011); a pull-based agent on the box would avoid the key but deploys a merge with nobody watching, and at one deploy every few days by one person the typed command is not the bottleneck. We chose **prebuilt images over on-box compilation** because a compile during a swap contends with two live web processes on one free-tier box, because a broken build then fails in GitHub rather than half-way through a deploy, and above all because stored tags make rollback "start the previous image" instead of "find the old commit and recompile." We chose **two fixed slots over a rollout plugin or DNS-discovered upstreams**: the plugin is unreadable third-party shell on a production box, and discovery fights Compose's replace-in-place behaviour, where two named slots are twenty lines anyone can follow. We chose to **skip the overlap for schema changes rather than adopt expand/contract discipline** — the standard alternative, where every migration must be readable by both the outgoing and incoming code, renames become two deploys days apart, and forgetting the rule means live errors for real visitors; five seconds of downtime on the rare schema deploy is a far cheaper price for one maintainer than a permanent rule enforced by memory at 1am. We chose the **private registry over public images**: the binary carries no secrets (config arrives from `.env` at boot per ADR-0003), but its SQL, route names, and internal logic survive compilation as readable strings, and publishing them concedes much of what a private repo was protecting. The costs we accept: the 500 MB free private-package allowance forces the prune step and caps retained versions around 18; two fixed slots do not generalise to N replicas, so scaling past one web process later means switching to discovery rather than extending this; both slots' memory is resident during a swap; **rollback is unsafe across a migration**, so schema deploys must be fixed forward; the inline post-write CDN purge goroutine (ADR-0012) is not in the drain's WaitGroup and is killed at swap, which is harmless only because the `purge_queue` row is the durable path; and no deploy happens while nobody is at a keyboard, which is a deliberate ceiling on how automated this can get.
