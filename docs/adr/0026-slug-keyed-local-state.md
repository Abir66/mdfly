# Local state is keyed by slug, not by file path

`~/.mdfly/state.json` stores one record **per slug** — the server-authoritative, immutable identifier — rather than mapping local file paths to slug lists. Each record carries `slug`, `url`, `manifest_hash`, `tier`, `size`, `file_count`, `created_at`, `updated_at`, `source` (`file` | `text`), and `path` (the absolute source path, or `null` for a [[Text Publish]]). The path → slugs relationship that `mdfly update <file>` needs is a **derived secondary index** built from the `path` fields at load time, not the primary key. Edit Tokens live separately in `~/.mdfly/credentials` (per [[Edit Token]]); a state record only notes that a token exists. Volatile data (the once-per-24h update check) lives in a separate `~/.mdfly/cache.json` so a corrupt cache can never clobber durable publish tracking.

We chose slug-keying over path-keying because the slug is the only stable identity in the system: a user who renames or moves `notes.md` after publishing has not changed the Document, and a path-keyed map would silently orphan the record — `mdfly list` would show a dead path, `mdfly update` would think the file was never published and mint a new URL. With slug-keying the record survives untouched; only its `path` goes stale, and it re-attaches with `mdfly update --slug <s>`. The cost we accept is that file-oriented lookups can no longer be an O(1) map hit — they scan the derived index — and one file legitimately maps to many slugs (every `publish` mints a new one), so `update <file>` must disambiguate (one → target it, many → interactive picker or required `--slug`, zero → error). That disambiguation is the same behavior ADR-0014 already required, so slug-keying adds no new UX surface, only a more durable substrate. Records also self-heal: a server `404`/`410` on update/delete prunes the stale entry automatically.
