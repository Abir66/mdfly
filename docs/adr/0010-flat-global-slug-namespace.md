# Flat global slug namespace: all Documents live at `/<slug>`

Every mdfly Document — Anonymous, Fresh-owned, or Claimed — is reachable at `mdfly.dev/<slug>` from a single global slug namespace. There is no `/<user>/<slug>` per-user URL form: the User's GitHub handle does not appear in the URL. Anonymous slugs are 8-char base62 server-generated; Owned slugs are either user-chosen `[a-z0-9-]{1,64}` (first-come-first-served against the global namespace) or a random fallback. A small reserved-word blocklist (`api`, `cdn`, `login`, `settings`, `_`, and similar future routing prefixes) is rejected at insert.

We chose this over a per-user URL namespace (`mdfly.dev/<user>/<slug>`) because URLs in this system are shared as links, not typed from memory — the value of a memorable, branded URL is small, while the value of a single uniform URL shape is large: routing is one pattern, Claim does not have to rewrite the URL, and the Anonymous-vs-Owned distinction stops leaking into the URL surface. The cost is real: squatting becomes possible (the first user to grab `notes` owns it forever), and we must maintain a reserved-word blocklist that grows whenever we add a new top-level route. We accept the squatting risk because the random-fallback slug always works as a safety valve and because we can reclaim individual names via direct DB action if abuse becomes a problem; we accept the blocklist maintenance burden because top-level routes change rarely. This decision also constrains future profile pages to a non-root prefix (e.g., `/u/<user>`), which we judge acceptable.
