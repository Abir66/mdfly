# SSR view path with `/llm/` raw-markdown twin, manifest stays server-side

**Supersedes ADR-0009. Amends ADR-0001 in place. Amended by ADR-0023** (apex routing now dispatched at edge by a Cloudflare Worker between Cloudflare Pages — landing/legal static — and this backend — slug SSR + LLM twin; precedence below still holds, runs at the Worker layer before reaching the backend; API paths move to `api.mdfly.dev/v1/*`).

When a viewer hits `mdfly.dev/<slug>`, the Go backend reads the Bundle Manifest from Postgres, fetches the requested markdown blob from R2, resolves every logical reference inline (asset paths → absolute `cdn.mdfly.dev/documents/<slug>/<hash>.<ext>` URLs; cross-`.md` links → absolute `mdfly.dev/<slug>/<path>` URLs for humans or `mdfly.dev/llm/<slug>/<path>.md` URLs from the LLM twin), renders the resolved markdown to HTML via Goldmark (GFM + frontmatter + chroma syntax highlight + bluemonday sanitize), and returns a fully server-rendered page with Preview Metadata `<meta>` tags. Multi-file bundles use path-suffix routing: `mdfly.dev/<slug>` serves the Root, `mdfly.dev/<slug>/<logical-path>` serves any nested `.md`. Mermaid diagrams and KaTeX math render client-side via tiny lazy-loaded shims that boot only when the rendered HTML contains a `mermaid` placeholder or math node — no React, no SPA, no client-side router; cross-document links full-reload (sub-100ms with SSR + CDN). A parallel **LLM twin** lives at `mdfly.dev/llm/<slug>` and `mdfly.dev/llm/<slug>/<logical-path>.md`, sharing the exact same resolution code path as the human routes but skipping the HTML wrap — returns resolved markdown as `text/plain; charset=utf-8` so AI agents (and `curl`) get self-contained bytes without running JavaScript. Cache-friendliness is the load shape that makes this work: both human and LLM routes are pure functions of `(slug, manifest_hash)` and ship `Cache-Control: public, max-age=300, s-maxage=86400` so Cloudflare absorbs the read fan-out; the backend renders once per Update for any popular Document, not once per view. Render-time budget caps protect against pathological inputs (>2s render returns 500; root markdown soft-capped at ~2 MB at Publish time as a separate Bundle Limits refinement). Single-flight by slug at the backend prevents cache-stampede on Update.

We chose this over (a) the original **inlined-manifest SPA** of ADR-0009: AI agents are a first-class read consumer of mdfly — agents and `curl` need self-contained markdown over HTTP without executing JavaScript, and the SPA's link-resolution layer made that impossible without duplicating resolution logic on the server anyway. Once resolution moves server-side for agents, having the SPA *also* resolve client-side is duplicated work and the JSON manifest is dead weight in the shell. We chose this over (b) **SPA fetches resolved markdown from a backend endpoint**: this is the half-step we briefly considered (backend resolves, SPA still renders); it pays the SPA's JS-bundle + blank-flash cost without buying anything the backend can't render itself, since the v1 viewer has no interactive state beyond Mermaid/KaTeX/copy-button — all of which work fine as progressive enhancements on top of static HTML. We chose this over (c) **rendering Mermaid + KaTeX server-side**: Mermaid in Go means shelling to a Node sidecar or embedding mermaid-cli via WASM, both of which substantially complicate the binary and the deploy story; KaTeX has Go ports but adds binary weight; lazy-loading the JS libs on demand keeps the no-JS-required floor for *content* (the markdown is fully SSR'd) and only gates *enrichment* (diagrams, math) on JS, which is the correct progressive-enhancement boundary. The real costs we accept: math and diagrams render ~one paint frame later than the rest of the page on first visit (cached on subsequent visits); the backend is on the per-view hot path for cache-miss requests (mitigated by aggressive CDN caching and single-flight, eliminated entirely once Cloudflare is configured in front per the pending domain/TLS branch); soft-navigation between linked `.md` files is full-page reload rather than client-routed (sub-100ms in practice with SSR + CDN, and removes a whole class of router-state bugs); and ADR-0001's "viewer SPA receives the Manifest inlined" claim is now obsolete — the Manifest stays Postgres-only and is consumed exclusively server-side. The amendment to ADR-0001 is narrow: storage layout (content-hash flat under `r2://documents/<slug>/<hash>.<ext>`), markdown-byte-identical upload, manifest-indirection-not-link-rewrite, and end-to-end content integrity are all unchanged; only the *consumer* of the Manifest moves from SPA to backend. Cross-doc Asset GC remains deferred per ADR-0017. The amendment to ADR-0017 is also narrow: "the view path's backend HTML shell + SPA + R2 fetch via `cdn.mdfly.dev`" rewords to "the view path's backend-SSR'd HTML + `/llm/` raw-markdown twin + R2 asset fetch via `cdn.mdfly.dev`", and the SPA-viewer deliverable is replaced by a Go-templated HTML viewer plus a ~5 KB progressive-enhancement JS bundle (copy-to-clipboard, mobile TOC drawer, lazy Mermaid/KaTeX boot).
