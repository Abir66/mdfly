# Domain & TLS: Cloudflare registrar + DNS + edge proxy, R2 custom-domain for `cdn`, Origin CA cert at DO, purge-on-commit

**Amended by ADR-0023** (apex `mdfly.dev` is now Worker-routed between Cloudflare Pages — landing/legal — and the backend — slugs/LLM; `api.mdfly.dev/v1/*` becomes its own subdomain with blanket cache-bypass; `app.mdfly.dev` reserved for v2 dashboard; the cache rules, purge surface, WAF/bot posture, and email-DNS records below all still apply but per-host as described in ADR-0023). **Amended by ADR-0024** (the `cdn.mdfly.dev` R2 bucket gains a CORS rule allowing the `https://mdfly.dev` origin so the Viewer's Raw toggle can `fetch()` the byte-identical source blob cross-origin; otherwise unchanged).

`mdfly.dev` is registered at **Cloudflare Registrar** (at-cost renewal, no markup) with **Cloudflare as authoritative DNS** so the proxy (orange cloud), R2 custom-domain feature, edge cache, and Universal SSL all live in a single dashboard. The apex `mdfly.dev` is a **CNAME-flattened** record pointing at the DO App Platform-issued hostname (`<app>.ondigitalocean.app`) with the orange cloud on, so Cloudflare terminates TLS at the edge and DO terminates again at origin with a **Cloudflare Origin CA cert** under SSL/TLS mode **Full (strict)** — the origin cert is only trusted by Cloudflare, making the origin hostname useless to any attacker who learns it. `cdn.mdfly.dev` is attached to the R2 bucket via Cloudflare's native R2 **custom-domain** connector (not S3-compat presigned URLs), so public GETs at `cdn.mdfly.dev/documents/<slug>/<hash>.<ext>` hit edge cache directly and never touch the backend; objects are content-addressed and PUT with `Cache-Control: public, max-age=31536000, immutable` so the CDN caches them forever and never needs busting. `www.mdfly.dev` is a CNAME with a `301 → https://mdfly.dev/$1` redirect via Cloudflare Bulk Redirect — one canonical URL, no backend involvement. **Cache rules at the edge**: `mdfly.dev/<slug>` + `mdfly.dev/<slug>/*` + `mdfly.dev/llm/*` cache-everything respecting the backend's `Cache-Control: public, max-age=300, s-maxage=86400` (ADR-0018); `mdfly.dev/api/*` bypasses cache entirely; `mdfly.dev/healthz` + `/cli/login` + `/abuse` fall back to Cloudflare defaults; `cdn.mdfly.dev/*` caches forever from the origin headers. Tier-Cache is enabled (free) to compress edge-miss fan-out through one upper tier before origin. **Cache invalidation on Update / Delete** is active, not lazy: backend calls the Cloudflare Purge API for four URL patterns per commit (`mdfly.dev/<slug>`, `mdfly.dev/<slug>/*`, `mdfly.dev/llm/<slug>`, `mdfly.dev/llm/<slug>/*`), fired in a background goroutine *after* the `commit` row flip — fire-and-forget with 3x backoff retry, log-and-alert on persistent failure. Purge success is not a commit precondition (a flaky Cloudflare API must not lose a user's commit); the worst case without purge is stale viewer up to the 24h `s-maxage`, recoverable via manual dashboard purge. **WAF / bot / DDoS posture** ships Cloudflare-defensive defaults: Bot Fight Mode on, Security Level Medium, Managed Challenge for borderline traffic, free WAF Managed Rules on, edge rate-limit rule of 10 req/min per IP on `/api/v1/publish/*` (defense-in-depth atop the backend's crude per-IP limit from ADR-0017), Always-Use-HTTPS on, HTTP/3 + 0-RTT on, min TLS 1.2. HSTS is intentionally **off in v1** — sticky-bricks the domain if HTTP is ever served, enable only after 1–2 months of stable HTTPS-only operation. The `/llm/*` path is a known false-positive risk for Bot Fight Mode (legitimate `curl` / agent traffic looks bot-shaped); v1 ships defaults, and if real telemetry shows agent-traffic blocks the carve-out is one custom rule. **Email DNS hygiene**: no transactional email in v1, so the domain advertises null-MX (`mdfly.dev. MX 0 "."`, RFC 7505), `SPF` of `v=spf1 -all`, and `DMARC` of `v=DMARC1; p=reject; rua=mailto:abir@shipday.com` — receivers reject any forgery of `@mdfly.dev`. **Search engine indexing**: every user Document is **noindex** — robots.txt serves blanket `Disallow: /` and every slug response (`/<slug>`, `/<slug>/<path>`, `/llm/<slug>`, `/llm/<slug>/<path>.md`) carries `X-Robots-Tag: noindex, nofollow`. Belt-and-suspenders: polite crawlers honor robots.txt, the header catches the rest (Google in particular honors both). Static pages (`/abuse`, future landing) get explicit `Allow:` lines when they exist; v1 has no marketing site, so blanket `Disallow: /` is correct.

We chose **Cloudflare for registrar + DNS + proxy + R2-custom-domain + WAF + cache** rather than splitting vendors because every single one of those features is free at the relevant scale, and the alternative — Namecheap/Porkbun for registrar + Cloudflare for DNS, or Route 53 + CloudFront + ACM, or fly.io edge — adds a second vendor for zero dollars saved and a worse R2 integration story (R2 custom-domain is Cloudflare-native; using it from a non-Cloudflare DNS authority is awkward at best). The lock-in is real (NS migration takes ~1h, R2 custom-domain is Cloudflare-only by definition) but the surface area is small and reversible at any time. We chose **orange cloud proxy on the apex** over grey-cloud-only DNS because ADR-0018's view path explicitly relies on edge cache (`s-maxage=86400`) to keep the backend off the per-view hot path; grey-cloud delivers nothing of the sort. The DDoS-absorption + origin-IP-hiding + free-WAF properties are bonus. We chose **R2 custom-domain over S3-compat presigned URLs** because public Documents (ADR-0008) gain nothing from presigning — the URL is already unguessable via content hash + slug — and presigning adds a CPU-per-request cost on the backend for an asset path that should never touch the backend at all. We chose **Cloudflare Origin CA cert at DO origin under Full (strict)** over Let's Encrypt because Origin CA certs are Cloudflare-only-trusted (rejecting any attacker who bypasses Cloudflare to hit the origin directly), 15-year validity (no renewal cron), zero-touch issue from the Cloudflare dashboard, and free — Let's Encrypt requires a 90-day renewal cron + DNS-01 challenge wiring that is pure operational tax when Cloudflare is the only client. The Full-strict mode is non-negotiable: "Flexible" sends plaintext to origin (Cloudflare itself becomes the MITM threat); plain "Full" accepts a self-signed origin cert (any attacker between Cloudflare and origin is MITM). We chose **CNAME-flattened apex over A-record** because DO App Platform doesn't expose a static IP at our tier and IPs rotate transparently on deploy — the DO hostname is stable, but the underlying IPs are not, so an A record would drift. Flattening is a free Cloudflare feature that makes apex-CNAME legal where RFC says it isn't. We chose **301 from `www` to apex** over dual-canonical because one canonical URL simplifies OG cards, future cookie scope (v2 dashboard), analytics, and SEO if we ever drop the noindex stance; 301 (permanent) over 302 (temporary) so browsers and CDNs memoize the redirect and the second-hop tax amortizes to ~zero. We chose **active Purge API on commit over relying on TTL alone** because "I updated my Document but the old version still shows" for up to 24h is the kind of small UX paper-cut that destroys user trust in the system; purging four URL patterns is two lines of code per commit and the failure mode (stale up to 24h on a Cloudflare API outage) is no worse than the TTL-only baseline. Fire-and-forget *after* the commit row flip is the right ordering: purge success is not a commit precondition, because a Cloudflare API outage must not destroy a user's commit, and the worst case is the same as the TTL-only baseline. We chose **null-MX + SPF -all + DMARC p=reject** over leaving DNS bare because spammers actively probe new domains for spoofable mail; the records cost nothing, deny everything, and reverse trivially in v2 when transactional email is added. We chose **`Disallow: /` + `X-Robots-Tag: noindex, nofollow` everywhere** over selective indexing because the user explicitly does not want search engines indexing user-published Documents — a 62^8 anon slug space depends on obscurity, and an anon user who shares a sensitive doc URL widely should not have Google amplify the leak. Owned-slug users who *want* SEO can self-publish off mdfly, or this stance can soften in v2 with a per-Document opt-in `meta` flag. The honest costs we accept: (a) Cloudflare is on the hot path for both apex and `cdn`, so a Cloudflare outage takes the whole site down — accepted because Cloudflare's SLA is strong and the alternative (multi-CDN) is preposterous overkill for v1; (b) Cloudflare Registrar doesn't support every TLD, but `.xyz` is supported and migration off the registrar (not the DNS) is straightforward; (c) Bot Fight Mode may false-positive on legitimate AI agent / `curl` traffic against `/llm/<slug>` — accepted with the known carve-out escape hatch; (d) Purge API requires Cloudflare API token storage in the backend env vars (one more secret to rotate), accepted as a normal operational footprint; (e) Origin CA cert renewal is 15-yearly which is long enough that the renewal procedure will need re-learning at the time — accepted, and a documented runbook covers it.
