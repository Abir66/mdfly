# v1 scope: ship the publish / own / claim loop, defer everything social

v1 ships exactly what validates the core loop — *publish from the CLI, share a URL, optionally claim it under an account* — and nothing else.

**In v1.** The CLI surface `publish` / `update` / `delete` / `remove` / `claim` / `login` / `logout` / `whoami` / `list`, with always-explicit verbs over slug-keyed local state (ADR-0009), Text Publish via `-m` or stdin, the `-r` recursive reference walk for a markdown Root, any-file Roots (ADR-0010), the global flag set (`--json`, `--plain`, `-v`, `-q`, `-y`, `--api`, `--no-update-check`), and the `MDFLY_TOKEN` / `MDFLY_API` / `MDFLY_CONFIG_DIR` env overrides. End-to-end publish, update, and delete over the two wire protocols with idempotency-key replay and optimistic concurrency (ADR-0006). Anonymous Documents with CLI-generated Edit Tokens, mode-0600 local secrets, and `logout --wipe-local` (ADR-0008), on a 30-day expiry. Owned Documents via OAuth loopback login with a `--device` headless fallback — **GitHub as the only provider at launch**, on the multi-provider schema (ADR-0007) — plus the `claim` flow that promotes an Anonymous Document to Owned. The flat global slug namespace with its reserved-word blocklist (ADR-0001). The server-rendered Viewer with sidebar file tree, directory listings, type-dispatched center, Raw toggle, `/_static/*` assets, and the `/llm/` twin (ADR-0010); GFM with frontmatter, Mermaid, KaTeX, and raw-HTML stripping; Preview Metadata extracted at view time (the `title`/`excerpt`/`og_image_hash` columns exist but stay NULL); a mobile-responsive viewer as a baseline, not a feature. Soft-delete at `410`, anon expiry at `410`, abandoned-init at `404`, all driven by the hourly lifecycle GC with 24-hour-grace blob deletion (ADR-0005). The durable CDN purge queue (ADR-0012). Two-layer rate limiting (ADR-0013). Bundle Limits enforced for both tiers. The Cloudflare edge posture with the Worker/Pages apex split carrying the legal and `/abuse` pages, `api.` and `storage.` subdomains, and blanket noindex (ADR-0011). A documented manual takedown process behind that abuse page. Deploy to the always-on free-tier VM with `/healthz` and in-process tickers (ADR-0003). Distribution via goreleaser to GitHub Releases plus a Homebrew tap and a curl install script.

**Deferred.** To **v1.5**: the marketing landing site in `apps/landing/` (the routing split ships in v1; only the copy is later). To **v2**: the browser dashboard at `app.mdfly.dev`; Google and any non-GitHub provider; `mdfly link --provider`; `mdfly sessions list` / `revoke`; named scoped API keys (the session token doubles as the CI credential in v1); `mdfly preview`; `mdfly export-token` / `import-token`; `mdfly rotate-token`; `mdfly doctor`; `--update-name`; folder publish and `--root`; commit-time population of the Preview Metadata columns; the inline-blob fast-path (wire fields reserved, never emitted); cross-Update asset garbage collection (within-slug terminal cleanup is in, cross-document dedup was never chosen so cross-document GC does not apply); view counters, analytics, custom domains, org/team documents, comments, search, edit history, theming, publish webhooks, and self-serve account deletion.

We chose this scope over an **anon-only beta with identity at v1.1** because `claim` — converting a throwaway share into owned content — is the most interesting idea in the design, so stripping it hides the actual product from feedback and makes the beta a worse pastebin; it would also defer OAuth machinery that is already designed, and replaying that design later costs more than building it once while every decision is fresh. We chose it over a **wider v1 with more providers, a dashboard, and view counters** because each provider costs its own app provisioning, callback testing, and failure-mode handling (one provider at launch is the smallest thing that still exercises the multi-provider abstraction), the dashboard is a separate frontend deliverable with its own session-cookie path that shares no code with the SSR viewer, and view counters are write-heavy on a read path currently absorbed almost entirely by the edge — moving every page view into the backend deserves real usage data first. We **defer `mdfly preview`** because shipping the GFM + Mermaid + KaTeX + sanitizer pipeline a second time inside the CLI binary (WASM or a Node sidecar) is substantial cost for a feature with a cheap workaround: slug-stable Documents mean publish-once-then-update-repeatedly is a fine iteration loop. We **defer the token-transport verbs** because Claim is the supported durable multi-device path and anyone with a genuine need can copy `~/.mdfly/credentials`; those verbs were ergonomic sugar, not enabling infrastructure. We **include rate limiting** rather than deferring it because the abuse vector is asymmetric — squatting the global namespace is cheap for a script and expensive for us to unwind (ADR-0013). We **include an abuse and takedown page** because hosting public user content without a documented takedown path is legal exposure regardless of user count; a static page with a mailto and a manual process is the floor. We **defer self-serve account deletion** because under roughly a thousand users a manual ticket beats designing the cascade blind (hard-delete owned Documents? soft-delete? orphan them into anon?) — each option has UX implications we lack data to settle, and rushing it locks in the wrong default; ADR-0005's `SET NULL` orphaning is the interim answer. The cost we accept: **v1 has no browser UI at all**, so every Owned-tier user touches the product exclusively through the CLI. That is a deliberate filter matching the launch audience, but it does mean non-CLI users can publish anonymously and read, and cannot meaningfully be Owned-tier until the dashboard ships. Trading dashboard polish for shipping `claim` earlier is the right trade for a product whose pitch is "your terminal is the editor."
